# 03 Web scaffold (plan)

## Goal

A Vite + React + strict TypeScript project in `web/` with:
- Tailwind themed from `design/style.md`;
- ESLint and Prettier;
- the `/api` dev proxy.

One page shows "Scorecaster" in the approved type and colours, and the API's `/health` status fetched through the proxy. That proves every layer from browser to `app.db`.

- `web/eslint.config.js`: adds `eslint-config-prettier` last.
- `web/.prettierrc.json`, and `format` and `check` scripts in `web/package.json`.
- `web/package.json`: `engines` pins Node 22.
- `web/.nvmrc`: `22`.
- `.editorconfig` (new, repo root): UTF-8, LF line endings, final newline, trimmed trailing spaces; 4-space indent for Python, 2 for everything else.

// web/vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tailwindcss from "@tailwindcss/vite";

export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    proxy: {
      // /api/health -> http://localhost:8000/health; nginx does the same in Docker
      "/api": {

## Risks

- **Version drift:** the template, Tailwind and Prettier versions are whatever's current when you run the commands. `package-lock.json` then pins them exactly.
- **The template's `eslint.config.js` shape varies by version.** The outline assumes `tseslint.config(...)`. If the generated file uses `defineConfig` instead, `prettier` goes last in that list the same way.
- **Tailwind v4 has no `tailwind.config.js`.** The theme lives in `index.css` under `@theme`, which is the current Tailwind way and keeps the tokens in one CSS file.
